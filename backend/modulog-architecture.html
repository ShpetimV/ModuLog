Relationships

Module → FieldDefinition OneToMany — one module has many field definitions
Module → ActivityLog OneToMany — one module has many log entries
ActivityLog → FieldValue OneToMany — one log has many field values
FieldValue → FieldDefinition ManyToOne — many values reference one field def

REST Endpoints

GET /api/modules get all modules for a user
POST /api/modules create a new module with field definitions
GET /api/modules/{id} get a single module with its fields
PUT /api/modules/{id} update module name, frequency, fields
DELETE /api/modules/{id} delete module and all its logs
GET /api/modules/{id}/logs get all activity logs for a module
POST /api/modules/{id}/logs log a new session with field values
DELETE /api/logs/{id} delete a specific log entry
GET /api/modules/{id}/status isOnTrack(), current streak

Suggested Build Order

1

Enums + base entities

Define FrequencyType and FieldType enums first, then write all 4 entity classes with JPA annotations.

FrequencyType.java FieldType.java Module.java FieldDefinition.java ActivityLog.java FieldValue.java
2

Repositories

One JpaRepository interface per entity. No implementation needed — Spring handles it.

ModuleRepository.java FieldDefinitionRepository.java ActivityLogRepository.java FieldValueRepository.java
3

Module CRUD (service + controller)

Get modules saving and returning from the database. Test with Postman or curl before moving on.

ModuleService.java ModuleController.java
4

Activity logging

POST a log entry with field values. This is the core feature — a session gets saved with all its dynamic values.

ActivityLogService.java ActivityLogController.java
5

Frequency logic

Implement isOnTrack() and streak calculation using the FrequencyType switch. Add /status endpoint.

FrequencyService.java
